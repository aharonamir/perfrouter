01

Problem & Motivation

TRouter (Phase 1) routes based on observed benchmark outcomes — it requires running every model on every task in WildClawBench before it can route. Adding a new model to the pool means re-running 60+ tasks across all models. That costs hours of compute and real API spend.

PerfRouter routes based on model properties — benchmark scores, Arena ELO, parameter counts, pricing. A new model can be added to the pool with just a YAML entry and an API key. No benchmark runs required.

The trade-off: PerfRouter's quality predictions are less accurate than TRouter's for models with no WildClawBench ground truth. The fix is to seed XGBoost with real WCB runs when available — and expand that seed set over time as models are used in production.

02

The Algorithm

Three components work together at routing time — all offline, no LLM calls.

Component A
Task Type Classifier
Encodes the incoming prompt with sentence-BERT (all-MiniLM-L6-v2). Computes cosine similarity against pre-computed embeddings of all 33 task type definitions. Returns the top-k most similar task types with similarity scores.
top_k = cosine_sim(encode(prompt),
          task_type_embeddings)
k = 3 ← weighted combination
Component B
XGBoost Quality Predictor
For each model, predicts expected quality score on the classified task type. Input: 46-feature vector with task-type affinity injected — all other affinity columns masked to NaN so XGBoost focuses on the relevant signal.
X = model_features.copy()
X[:, other_affinities] = NaN
X[:, active_affinity] = score
quality = xgb.predict(X)
Component C
Cost-Adjusted Routing
Applies cost adjustment using runtime pricing from models.yaml — not training-time costs. Applies eligibility filters: context window, vision capability, cost cap. Returns the model with the highest adjusted utility.
utility = quality − α × norm_cost
eligible = context ∩ vision ∩ cap
chosen = argmax(utility[eligible])
chosen_model = argmax over eligible models of
     predicted_quality − α × normalised_cost
Standard mode (α=0.3 default)
Maximises adjusted utility — best quality at lowest cost. Models more than 2× baseline cost are excluded.
chosen = argmax(quality − 0.3 × cost)
Degradation threshold mode
Accept any model within X% of best quality, then pick the cheapest of those. Increases routing diversity dramatically.
floor = best_quality × (1 − threshold)
band = models where quality ≥ floor
chosen = cheapest(band)

Data Sources

📊
Artificial Analysis API
Free-tier API providing benchmark scores and performance metrics for 527 models. Fetched once per pipeline run. Used for objective capability scores across coding, reasoning, and knowledge tasks.
aa_intelligence_index aa_coding_index aa_math_index livecodebench gpqa hle terminalbench tau2 speed_tps latency_ttft
🏆
Arena.ai ELO (wulong.dev API)
Human preference ELO scores across 5 categories. Fills the gap for task types where automated benchmarks have no coverage — social interaction, creative writing, document understanding.
arena_text_elo arena_search_elo arena_code_elo arena_vision_elo arena_document_elo
🧪
WildClawBench Ground Truth
Real agent benchmark scores for the 3 models we ran (V4 Flash, V4 Pro, GPT-OSS). Used as high-confidence seed rows in XGBoost training (weight=3.0 vs 1.0 for benchmark-derived rows). Expands as more models are run in production.
wcb_avg_score wcb_avg_nonzero wcb_zero_rate
⚙️
models.yaml (manual specs)
Operator-maintained config with pricing, context windows, and capability flags. Runtime pricing is read from here at inference — not from training-time data — so price changes take effect immediately on restart without retraining.
price_input_per_1M price_output_per_1M effective_context_k supports_vision is_reasoning total_params_B
04

Feature Vector — 46 Features Per Model

Task-type affinities
33
One per task type. Weighted average of benchmark scores using the benchmark→task-type weight matrix. At inference, only the active task type's affinity is non-NaN — the rest are masked.
Structural features
9
total_params_B, active_params_B, moe_density, context_window_k, effective_context_k, context_headroom_ratio, speed_output_tps, latency_ttft_s, latency_e2e_500_s
Boolean flags
5
flag_reasoning, flag_thinking, flag_vision, flag_tools, flag_free — encoded as 0/1 integers for XGBoost compatibility.
WCB seed scores
3
wcb_avg_score, wcb_avg_score_nonzero, wcb_zero_rate. NaN for models without benchmark runs. XGBoost handles NaN natively.

Pricing features are excluded from XGBoost — cost is applied at decision time using runtime prices from models.yaml, not learned by the model. This keeps quality prediction separate from cost adjustment and allows α to be changed at runtime without retraining.

Next Steps

Immediate · Validation
Validate Mimo & Hy3 in Production
PerfRouter already routes to Mimo and Hy3 based on their AA benchmark scores — no WCB runs needed. Adding a new model requires only a models.yaml entry and re-running the pipeline (~2 minutes).

Validation happens naturally through production traffic — if a model underperforms its benchmark prediction, optmod's escalation layer catches it. Optional: run WCB on specific models if you suspect benchmark scores are misleading for your task distribution.
Short Term · Integration
Expose Threshold in optmod
Add PERF_ROUTER_DEGRADATION env var to perf_router_router.py so operators can tune quality/cost tradeoff per deployment without retraining. Pass it through from ctx if optmod exposes per-request quality preference.
Medium Term · Production
Online Learning from Logs
Every completed optmod request is implicit feedback — we know which model was used, the token counts, and eventually the outcome. Build a log parser that converts routing logs into additional WCB-equivalent training rows, continuously improving PerfRouter's quality predictions as real traffic flows through.
